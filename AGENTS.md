# AGENTS.md

A dashboard of client counts over time: a stacked bar chart and an expandable table.

## Structure

```
packages/
  design-system/              UI components. No domain words.
    tokens/                   The Panda preset: colours, spacing, text styles.
    css/                      The Panda `css`, `cva` and `cx`, re-exported for the web app.
    components/
      index.ts                Re-exports every component of the design system.
      stack/                  `VStack` and `HStack`, generated by Panda.
      page-layout/            `PageLayout`: the `main` landmark with the page's padding and spacing.
      table/
        utils/                Pure TypeScript. `drill-down.ts`: which rows of a tree are expanded and which one is selected.
      stacked-bar-chart/
      error-boundary/         `ErrorBoundary`: catches an error and shows a fallback with a retry.
      avatar/  button/  card/  icon/  skeleton/  typography/
  domains/                    Pure TypeScript. No React.
    book-of-business/
      types.ts                Wire types (`*Dto`) and domain types (`BookNode`, ...).
      constants.ts            The twelve months.
      mappers.ts              Pure functions from one shape to another: `toBookNode`, `toChartData`.
      mappers.test.ts
      mocks.ts                Payloads for tests, stories and e2e mocks.
  web-app/                    The React app.
    playwright/gallery/       The page that renders one story for a component test.
    src/
      api.ts                  The ky client.
      main.tsx
      domains/
        book-of-business/
          requests.ts         Functions that call the API and return domain types.
          queries.ts          TanStack Query hooks around the requests.
          components/
            index.ts          Re-exports every component of the domain.
            book-dashboard/   Loading, error and loaded states.
            book-trend-chart/
            book-breakdown-table/
      pages/
        clients.tsx           The page title and the dashboard.
        clients.e2e.ts
  server/                     Node.js REST API.
    index.ts                  The server. It also serves the built web app.
    routes.ts                 The one route.
    mock-db.ts                The data it serves, in place of a database.
  e2e/                        Playwright.
    web-app/
      playwright.config.ts    Two projects: `e2e` (`*.e2e.ts`) and `components` (`*.ct.ts`).
      index.ts                Composes the fixtures into `test`.
      fixtures/
        api.ts                Mocks any `/api/<path>` request: `respond`, `fail`, `hold`.
        clients-page.ts       Locators and user actions for the clients page.
```

### A component folder

```
book-dashboard/
  index.ts                    export * from './book-dashboard'
  book-dashboard.tsx
  book-dashboard.styles.ts    Every `css` and `cva` call of the component.
  book-dashboard.story.tsx    One named export per scenario a test mounts.
  book-dashboard.ct.ts        The component test.
```

### Where a new thing goes

- A new domain gets a folder in `packages/domains` (`types.ts`, `constants.ts`, `mappers.ts`, `mocks.ts`) and a folder in `packages/web-app/src/domains` (`requests.ts`, `queries.ts`, `components/`).
- A component that knows the domain goes in that domain's `components/`. A component that does not goes in `design-system/components`.
- A page stays thin: `PageLayout`, a title and domain components.

## Imports

- Inside the web app, import across folders through `@web-app/*` (`packages/web-app/src/*`).
- Import a domain's components from the folder: `@web-app/domains/book-of-business/components`.
- Components inside that folder import each other relatively (`../book-trend-chart`), so the index never imports itself.
- Import styles as `import * as styles from './<component>.styles'`.
- The web app imports `css` from `design-system/css`. The design system imports it from its own `../../styled-system/css`.
- The web app imports every design-system component from `design-system/components`.
- Inside the design system, components import each other relatively (`../button`), so the index never imports itself.
- The table's drill-down comes through its namespace: `Table.createDrillDown`, `Table.pressRow`.
- Import domain code by file: `domains/book-of-business/types`.

Packages import one way:

- `design-system` imports no other package.
- `domains` imports no other package.
- `web-app` imports `design-system` and `domains`.
- `server` imports only wire types from `domains`.
- `e2e` imports no other package. The specs live in the web app and take their mock payloads from `domains`.
- A component test imports `test` and `expect` from `@playwright/test`. It imports a story only as a type.

## Stack

- npm workspaces, Node 24, TypeScript 7
- React, Vite, Panda CSS, React Aria Components
- ky, TanStack Query, react-error-boundary, ts-pattern, Recharts
- Vitest for pure code, Playwright for component and e2e tests
- Server: plain `node:http`, no framework

## Rules

### Naming

- The domain is `book-of-business`. The page is `clients`.
- Say `advisor`, not employee. Say `acquisitionChannel`, not channel.
- Say `expanded` and `collapsed`, not opened and closed.
- Files and folders use kebab-case.

### Code

- Keep it simple. Prefer what a library gives out of the box over custom code.
- TypeScript is strict. ESLint must pass with zero warnings.
- Use ts-pattern to branch on union types.
- Add `memo` and stable callbacks only where a re-render was measured.
- No demo-only branches in product code, such as query flags or `import.meta.env.DEV` checks. Mock the state in a test.
- Write a comment only for a reason the code cannot show.

### Components

- Prefer composition over props: `Table.Root`, `Table.Row`, `Table.Cell`.
- Design-system components know nothing about the domain. A row takes `level` as a number. The chart takes `series` and `categories`.
- Lay out with `VStack` and `HStack` from `design-system/components`. Their spacing props take the spacing tokens: `gap="16"`.

### Data

- Do not change the wire format.
- Map wire types to the model in one function only: `toBookNode` in `mappers.ts`.
- Show every value as the API sends it. Never compute a parent from its children.
- `requests.ts` holds request functions. `queries.ts` holds the hooks.

### Table

- Build the table on React Aria's `Table` and `Virtualizer`. Do not add another table or virtualisation library.
- Rows nest recursively. Any depth must work.
- Show a chevron only on rows that have children.
- A click on a row with children expands or collapses it.
- The chart shows the selected row: its children stacked, or the row on its own when it has none. Expanding a row selects it. Collapsing the selected row, or a row above it, selects the collapsed row's parent.
- Do not hand-write ARIA attributes or key handlers. React Aria provides them.
- Expand and collapse must work from the keyboard.
- Only the chevron animates. Do not animate rows.

### Tests

- Unit tests of pure code sit next to it as `*.test.ts` and run in Vitest.
- Component tests sit next to the component as `*.ct.ts` and run in Playwright. Do not add Testing Library or jsdom.
- A component test mounts a story: `mount('table/Collapsed')` renders the `Collapsed` export of `table.story.tsx`.
- A story is one scenario: the component with its props and data. Prefer a new story over a parameter.
- E2E specs sit next to the page as `*.e2e.ts`. Keep them to high-level flows.
- A page spec describes what the user does and sees. How it is done lives in the page fixture: `clientsPage.expand('Branch 1')`.
- Happy-path e2e runs against the real API. Loading and error states use the `api` fixture.
- Take test payloads from `domains/<domain>/mocks`.
- Do not test constants.

